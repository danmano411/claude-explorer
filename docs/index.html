Claude Explorer

A file manager built around one thing: launching Claude Code from any folder in one action — and keeping every session you start somewhere you can actually see it.

v0.10.1 GitHub Releases Apache-2.0

01Install & requirements

Claude Explorer launches the Claude Code CLI you already have. It does not bundle one — install Claude Code first and make sure claude runs in a terminal.

From a release

  1. Download the artifact for your platform from the Releases page.
  2. Run it. On Windows you get a Desktop shortcut and a Start Menu entry, plus an Open in Claude Explorer entry on the right-click menu of any folder.
  3. Running a newer installer later upgrades in place and keeps your settings, recent folders and workspace.

From source

git clone https://github.com/danmano411/claude-explorer.git
cd claude-explorer
npm install
npm run package     # -> dist/Claude Explorer Setup x.y.z.exe

npm run dev         # or: live development
Windows is the tested platform. macOS and Linux builds ship from the same release but have had far less real-world use. See Platforms & updates for the differences that are deliberate.

02How it fits together

Three ideas carry the whole app.

Tabs

A tab is independently one of three things:

TabWhat it isHow you get one
FilesA folder listing — the File Explorer half.The + button, Ctrl+T, File ▸ Open Recent, the CLI, or the Explorer right-click verb.
TerminalA live terminal: either a Claude session or a plain shell.The → arrow on any folder row; File ▸ Open Recent; the tab menu's Open Terminal.
ViewerA read-only file view, or a git diff.Double-click a file; Show changes on a modified file.

Spaces

Separate named workspaces. Each one owns its own tabs, its own split layout and its own remembered active tab. One space per project is the intended shape. A tab belongs to exactly one space — moving it to another space removes it from the first.

Session awareness

Every Claude session reports what it is actually doing — working, waiting on you, finished — read from Claude Code's own hooks rather than guessed from terminal output. A session blocked in a space you are not looking at marks its tab, its space and the spaces menu, so it cannot stall unnoticed.

Editing stays in Claude. The file viewer is read-only on purpose. This app's job is to supervise the AI doing the editing — browse, launch, watch, review the diff — not to be a worse version of two tools you already have.

03Browsing files

A files tab is a single-column listing: directories first, then files, each sorted by name. There is no size or date column and no sort control.

What a row can show

  • A git status letter in the left gutter (see Git & the diff view).
  • A folder or file icon, and the name.
  • ↗ if the entry is a symlink or junction.
  • On folders only, a → button: Open this folder in Claude. It starts a Claude Code session rooted there without navigating into the folder.

Getting around

The address bar checks that the path exists before navigating; a path that does not resolve leaves you where you are. Esc cancels the edit.

Everything below is reversible with Ctrl+Z except permanent delete, which says so first.

New Folder and New File both drop you straight into the rename box on the new item, so you can name it without a second gesture. Copy and Cut also put the selected paths on the system clipboard as text, so you can paste them into a Claude prompt — unless a real file-drop is already on the clipboard, which is left alone.

Where deleted files go

A delete does not go straight to the Recycle Bin. Each item is first staged into a .claude-explorer-trash folder on the same drive, with a manifest recording where it came from. That is what makes Ctrl+Z a cheap, reliable rename back into place rather than a best-effort Recycle Bin restore.

Staged items are handed to the real Recycle Bin when their undo life is over, and a full sweep runs on quit. Anything left behind by an unclean exit is recovered at the next launch. On a volume with no Recycle Bin — a network share, say — items stay staged and you are told they will be retried next launch.

The undo stack holds the last 100 operations and covers delete, rename, move, copy, new folder and new file. A rejected undo leaves both stacks untouched.

Permanent delete is genuinely permanent. Shift+Delete skips the staging folder entirely, so there is no undo entry to use afterwards. It is refused outright in Explorer mode.

Right-click menus

On a file or folder: Open · Open in Claude (folders) · Open in external terminal (folders) · Show changes (modified files) · Open in default app (files) · Cut · Copy · Paste · Rename · New Folder · New File · Delete · Reveal in File Explorer.

On empty space: Paste · New Folder · New File · Reveal in File Explorer.

05Drag and drop

You can drag between folders, between tabs, and between panes of a split.

GestureResult
Drag within one driveMove.
Drag across drivesCopy. A cross-volume move is not silently attempted.
Ctrl+dragCopy, always, whichever drive you land on.
Right-dragDrops a small menu at the cursor: Move here · Copy here · Cancel.
Drop onto a folder rowInto that folder.
Drop onto empty list spaceInto the folder you are currently viewing.

Dropping an item into the folder it already lives in does nothing. If any item in the drag — or the destination — is already busy with another operation, the whole drop is refused rather than half-applied.

Shift+drag is not a move modifier here. Unlike Windows Explorer, holding Shift currently changes nothing: only Ctrl (force copy) and the source/destination drives decide the outcome. Use right-drag if you want to pick explicitly.

06Search

Ctrl+F opens the search box over the current pane. It works in two tiers from one input:

  • As you type — an instant, case-insensitive filter of the folder you are already looking at. Filenames only, no disk access.
  • On Enter — a recursive search rooted at the current folder using bundled ripgrep, matching file contents as well as names, streamed in as it finds things.

In the results: ↑ / ↓ move the highlight, Enter opens the highlighted hit, Esc closes.

BehaviourExplorer modeDeveloper mode
Files ignored by .gitignoreSkippedSearched
Hidden files and dotfilesSkippedSearched

Results stop at 2000 hits and say so (2000+ (stopped early)); each preview line is trimmed to 300 characters. If the ripgrep binary is missing the search degrades to names only and tells you.

07Git & the diff view

Inside a git repository, every row carries git's own status letter in the gutter.

MarkMeaning
MModified
AAdded — staged
DDeleted
UNew — not tracked by git yet
RRenamed
·This folder contains changes

Files git reports as deleted still appear, as struck-through ghost rows. Double-click one to see what was removed.

Show changes

Show changes on a modified file opens a coloured unified diff in a viewer tab. Two things about it matter in practice:

  • The line numbers are real file line numbers taken from the hunk headers — the number you can type back into Claude, not a position within the diff.
  • It diffs against HEAD, not the index, so work Claude has already staged still shows a real diff instead of an empty pane.

A binary change says so rather than rendering garbage. There is no side-by-side mode.

Keeping up with a live session

The gutter refreshes when the terminal next door goes quiet: after the last byte of terminal output settles, git status is re-read, and if nothing is mid-flight — no rename box open, no menu, no drag, no selection in progress — the listing reloads too. So you can watch a session edit while you browse.

08File viewer

Double-clicking a file opens it in a read-only viewer tab with syntax highlighting.

Recognised by extension: TypeScript/TSX, JavaScript/JSX, JSON, CSS, HTML, Markdown, shell, PowerShell, YAML and TOML. Anything else — including extensionless files like LICENSE and dotfiles like .gitignore — renders as plain text, which is a normal outcome, not a failure.

Limits, and why they exist

LimitWhat happens past it
5 MBRefused without reading — Too large to preview.
20,000 lines / 2M charactersTruncated, with a banner saying so.
200,000 charactersStill shown, but as plain text — highlighting that large blocks the UI long enough to feel like a hang.
Binary contentRefused, with an Open in default app button. There is no inline image preview.

The viewer deliberately cannot edit or save. Reading is never blocked by Explorer mode — only mutation is.

09Tabs & groups

Pinning

Pin a tab from its right-click menu. Pinned tabs shrink to their icon and hold at the left of the strip, Chrome-style. A pinned tab cannot be closed until you unpin it, and cannot belong to a group.

Tab groups

A group is a named, coloured, contiguous run of tabs — deliberately not tied to a directory, so it can mean whatever you need it to. From the tab right-click menu: New group from this tab, then rename, recolour (Clay, Sage, Sand), collapse, ungroup, or close the group's tabs.

With Group new tabs with their source on (the default), a viewer or shell tab opened from a grouped tab joins that group automatically.

Reordering

Drag a tab along the strip. Where it lands decides its group: dropped inside a run it joins that group, dropped in open space or exactly on a seam it comes out ungrouped. Pinned tabs only reorder among themselves.

Closing

Closing is only confirmed when something unrecoverable would die with the tab — confirming every close just trains you to click through.

TabAsks?
Files or viewer tabNo
Terminal whose process already exitedNo
Plain shellOnly if it is running something. A shell sitting idle at its prompt closes silently.
Claude sessionUnless the session reports itself idle. Working or awaiting-input asks; so does an unknown state.

Closing several tabs at once asks once, naming how many are live. Deleting a space always asks — and tells you which of its tabs are live and how many pinned tabs will go with it, since deleting a space closes pinned tabs too.

10Spaces

The spaces button sits at the left edge of the tab strip. It carries a flag when a session in another space is waiting on you.

ActionHow
Switch spaceCtrl+1..9, or click a row in the menu
Switch to a pinned spaceCtrl+Shift+1..9
Cycle spacesHold Ctrl+Tab / Ctrl+Shift+Tab
New spaceSpaces menu ▸ New empty space
Rename / delete / pinSpaces menu
Colour a spaceSpaces menu ▸ Color — a preset, or Custom… for your own light and dark values
Move a tab or group to another spaceMove Tab to ▸ / Move Group to ▸, or drag it onto a row in the spaces menu

Hold-to-preview cycling. Holding Ctrl and tapping Tab works like Alt-Tab: after a short grace period a panel appears listing your spaces, each further tap advances the highlight, and releasing Ctrl commits one switch. Esc mid-hold cancels without switching — and is swallowed, so it will not also interrupt a Claude turn underneath. Tapping quickly still switches instantly with no panel.

Spaces sort pinned-first, both in the menu and in cycling order. A space cannot be deleted if it is pinned or if it is the last one. All four space shortcuts are rebindable.

A space remembers its tabs and their order, which tab was active, its split layout and divider positions, its colour and whether it is pinned.

11Split view

Any space can split into a grid of panes, each with its own tab strip.

Making a split

  • Drag a tab to the edge or corner of a pane to split or dock there.
  • Tab menu ▸ Split right / Split down (offered once the strip holds at least two tabs).
  • Ctrl+Shift+G opens a spreadsheet-style picker — hover or arrow-key out an M×N arrangement up to 5×5, Enter applies it.

Adjusting

  • Resize: drag a divider, or focus one and use the arrow keys. Panes have an 80 px floor.
  • Move a pane: drag it by its strip background to swap with or dock beside another; or Ctrl+arrow inside the grid picker. Alt+drag on a pane body does the same from anywhere in the pane; Esc aborts a drag in progress.

Closing a pane's last tab removes that pane and hands its rectangle to a neighbour; closing a pane merges its tabs into the neighbour instead. Nothing is ever lost, and dropping below two panes quietly returns you to a single strip.

Terminals survive all of this. Rearranging a split never unmounts or re-parents a terminal — only its grid position moves — so scrollback and a running Claude turn are untouched.

12Terminals

Terminal tabs come in two kinds. A Claude session runs the claude CLI; a shell is a plain prompt.

PlatformShell used
Windowspowershell.exe -NoLogo
macOS$SHELL -l — a login shell, so Homebrew and ~/.local/bin are on PATH
Linux$SHELL, or /bin/bash

Claude Explorer finds the claude executable itself by scanning PATH plus ~/.local/bin (and Homebrew's directories on macOS), because neither Windows nor a Dock-launched macOS app resolves a bare command name the way your shell does.

Keys inside a terminal

KeyBehaviour
Ctrl+V / Ctrl+Shift+VPaste. Clipboard text wins if present. If the clipboard holds only an image and this is a Claude tab, the keystroke is handed to Claude Code, which reads and attaches the image itself.

13Session awareness

Claude Explorer injects HTTP hooks into the sessions it launches, so a session reports its own state instead of the app guessing from terminal output.

StateMeans
workingA prompt was submitted, or a tool is running.
awaiting-inputClaude is blocked on you — usually a permission prompt.
idleThe turn finished; the session is waiting for your next prompt.
stoppedThe process exited. Derived from the process itself, never reported by it.

An unknown state is never treated as any of these. Sessions Claude itself spawned, and sessions started with agent control switched off, run without hooks and simply report nothing.

Where state shows up

  • A coloured dot on the tab, with a distinct marker — not just a colour — when a session needs you.
  • A flag on the spaces button when a session in another space needs you, and on that space's row in the menu.

What you can turn on

The markers are always on. Three opt-ins sit in Settings, and the first-run card offers them once:

  • A sound — a short chime the moment a session starts waiting on you.
  • A desktop notification — suppressed when the app is focused and that tab is already on screen, so it only fires when you would actually miss it.
  • Jump to the session that needs input — held back for a moment if you are mid-keystroke somewhere else, and skipped if the tab you are looking at is itself waiting.

17Command line

FlagDoes
--open <path>Opens a folder in a files tab, or a file in the viewer.
--new-session <folder>Opens that folder, ready for you to start a session in one click. Refused on a file path.
 
"Claude Explorer.exe" --open C:\repos\my-project
"Claude Explorer.exe" --new-session C:\repos\my-project

If the app is already running, these open in the existing window rather than starting a second copy.

Neither flag starts Claude by itself. That is deliberate, not an omission: the command line of a running app is reachable by any local process, so --new-session stages the folder and leaves the actual launch to a human click. There is no code path from a command-line flag to a spawned session.

Windows Explorer integration

The installer adds Open in Claude Explorer to the right-click menu of any folder, and of the background of any open folder. It is registered per-user, so installing needs no administrator rights. On Windows 11 it lives under Show more options (Shift+F10) along with other classic shell verbs. Uninstalling removes it.

18Explorer vs Developer mode

Two modes, toggled from the status bar button or Ctrl+Shift+D. This is a guardrail against mis-drags and mistaken deletes — yours or an AI's — not a security sandbox: the app runs a real shell for you on request.

Explorer (default)Developer
Hidden files and dotfilesHiddenShown, dimmed
Windows noise ($RECYCLE.BIN, System Volume Information, pagefile.sys, desktop.ini, Thumbs.db…)HiddenShown, dimmed
SearchHonours .gitignoreSearches everything
Changing a system pathRefused, with a plain-English reasonAllowed after typing CONFIRM
Permanent deleteRefusedAllowed after typing CONFIRM

What counts as a protected path

The rule matches the folder and everything beneath it. Browsing is never restricted — only mutation.

WindowsmacOS / Linux
SystemC:\Windows, C:\Program Files, C:\Program Files (x86), C:\ProgramData/System, /Library, /usr, /bin, /sbin, /etc, /lib, /boot
Drive rootsC:\ and any UNC share root/ and mount containers like /Volumes, /mnt, /media

Your home directory, /Applications and /opt are deliberately not protected — that is where your work lives.

The trash staging folder is off-limits in both modes. Changing it would break a pending undo, so no mode unlocks it.

Every one of these decisions is made in the main process, not in the UI, so no call site can forget to ask — including the ones an agent reaches.

19Agent control (MCP)

Sessions launched by Claude Explorer can drive the app itself, through a small MCP server the app runs in-process.

ToolParametersDoes
list_tabsnoneLists every tab: id, kind, folder, title, and for terminals their status.
close_tabtabIdCloses that tab, ending its process. It never guesses a target.
open_viewer_tabpathOpens a git diff for that file, so it can show you something. Returns no file content.
open_claude_sessionpathStarts a new Claude session in a new tab at that folder.

The security model

The server binds to 127.0.0.1 only, on an ephemeral port, and every request must carry a bearer token minted fresh each time the app runs and never written to disk. The token is the whole authentication: an unauthenticated local process gets a 401. Every path argument is validated and resolved before any tool acts on it.

Three limits worth knowing

  • Spawning throttles, it does not refuse. Below your free allowance, open_claude_session opens a tab silently. At or above it, dead agent tabs are reaped first, and if that does not free a slot you get a modal naming the folder in full. An approval always starts the session — there is no count at which the tool simply says no. Because reaping returns slots, the number bounds concurrent sessions, not lifetime ones. A denial arms a brief cooldown so a session cannot spam you.
  • Fan-out cannot compound. A session started by the tool gets neither the tools nor the token, so it structurally cannot open further sessions. It also gets no state hooks, which is why an agent-spawned tab shows no status dot.
  • One switch removes all of it. Settings ▸ Let Claude sessions control Claude Explorer. Off stops the server immediately; sessions already running keep whatever they were launched with.

An app installed from a release checks GitHub Releases on start, downloads in the background and offers to restart. Built from source, auto-update is off — local builds are not tied to the release feed.

macOS: the app is not notarized, and Gatekeeper will say so

Claude Explorer is not signed with an Apple Developer ID and is not notarized — that needs a paid Apple Developer Program membership this project does not have. Nothing is wrong with your download; Apple simply has no way to attest to it. The first time you open it, macOS refuses and says it cannot verify the app is free of malware. To open it anyway:

  1. Try to open the app once, so macOS records the refusal.
  2. Open System Settings ▸ Privacy & Security, scroll to the message about Claude Explorer, click Open Anyway, and confirm.
  3. On macOS 14 and earlier, right-clicking the app and choosing Open also works. macOS 15 removed that shortcut.

Builds up to v0.10.1 carried an incomplete signature, so macOS may instead say one of those "is damaged and can't be opened", or open nothing at all. Nothing is damaged: xattr -cr "/Applications/Claude Explorer.app" clears the quarantine flag.

You do this once per installed version. Auto-update is switched off on macOS as a direct consequence: macOS verifies an update against the app's Developer ID signature before installing, so a build without one cannot update itself. Rather than download ~100 MB on every launch and fail at the last step, the app does not try. Watch the Releases page and drag the new DMG over the old app.

Linux

Download the AppImage, chmod +x it, run it. Two differences from Windows, neither a bug: the unread-session badge goes through the Unity Launcher API, so Unity, KDE and GNOME-with-Dash-to-Dock show it while plain GNOME Shell shows nothing (the in-app markers work either way); and Open in Terminal tries a list of known terminal emulators, declining rather than guessing if none is installed.
