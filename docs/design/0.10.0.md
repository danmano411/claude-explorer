# 0.10.0 — Session awareness and space identity

**Status:** design, approved to implement.
**Jira:** epics KAN-71 (M8) and KAN-72 (M9); tickets KAN-73 … KAN-94.
**Date:** 2026-07-31.

This document is the synthesis the tickets do not contain: the architecture of the
new state signal, the exact contracts, the branch plan, and the testing strategy.
Per-ticket scope and acceptance criteria live in Jira and are not repeated here.

---

## 1. Why this release is shaped the way it is

Two of the five asks were reported as separate bugs. They are one bug, and it is
the same missing capability the largest feature needs.

`src/renderer/ptystatus.ts` decides what a Claude session is doing by watching
**byte traffic on the pty**:

```
pty:data          → running
700 ms of silence → waiting
pty:exit          → stopped
```

Bytes are not intent. Consequences, all reported independently:

| Symptom | Cause |
|---|---|
| Dot turns green while typing | A terminal echoes keystrokes; an echo is `pty:data` |
| Dot flickers amber on tab switch | Any output gap >700 ms crosses the idle line |
| Red never appears | There is no red — `index.css:437-439` is green / amber / dim grey |
| A restored tab pulses green | `TabBar.tsx:425` defaults `?? 'running'` for a tab with no pty at all |
| Finished session warns "still running" on close | `closeguard.ts:54` treats anything but `'stopped'` as live |

And the notification feature is impossible on this signal, because "needs your
permission", "finished its turn" and "thinking quietly" are all *silence*.

So 0.10.0 is sequenced around one frozen contract — a real session-state signal —
with the two bug fixes and the whole notification surface fanning out from it.

## 2. The state signal (KAN-73)

### 2.1 Source

Claude Code's own hook system. The matchers were verified in the installed
binary (`~/.local/bin/claude.exe`, v2.1.220), not inferred from documentation:
`permission_prompt`, `idle_prompt`, `auth_success`, `elicitation_dialog`,
`elicitation_complete`, `elicitation_response`, `agent_needs_input`,
`agent_completed`.

### 2.2 The state machine

Five hook registrations produce a total state machine:

| Hook | Transition |
|---|---|
| `UserPromptSubmit` | → `working` |
| `PreToolUse` | → `working` (this is what clears `awaiting-input` after approval) |
| `Notification` / `permission_prompt` | → `awaiting-input` |
| `Notification` / `idle_prompt` | → `idle` |
| `Stop` | → `idle` |
| `pty:exit` (existing IPC, not a hook) | → `stopped` |

`PreToolUse` is included **only** as a leave-transition. It fires before every
tool call in every permission mode, including bypass, so it must never be read as
"permission needed" — that is what `permission_prompt` is for.

### 2.3 The type

```ts
/**
 * What a Claude session is actually doing, as reported by Claude Code's own
 * hooks — NOT inferred from pty traffic. Absence from the map means UNKNOWN and
 * must render as unknown: there is no optimistic default (KAN-74).
 */
export type ClaudeState = 'working' | 'awaiting-input' | 'idle' | 'stopped'
```

`PtyStatus` stays exactly as it is and keeps serving shell tabs, where "bytes are
moving" genuinely does mean "something is running". Two types because there are
two questions; collapsing them is what produced this release's bugs.

### 2.4 Injection

`claude --settings <path>`, confirmed present in `claude --help` on this machine.
A settings JSON is written into userData beside the existing
`mcp-agent-control.json` and its **path** is passed at the same site as
`--mcp-config` (`pty.ts:279`).

A path, not inline JSON. `pty.ts:163-208` documents at length how a fourth quote
on the command line breaks cmd.exe's exemption rule and stops Claude launching;
inline JSON is nothing but quotes. The path form is already proven through that
quoting path.

The blob also sets `messageIdleNotifThresholdMs: 5000`. The default is 60000
(verified in-binary), which would make "finished" arrive a minute late.

Deliberately **not** `~/.claude/settings.json`: that would change Claude Code's
behaviour for every session on the machine, including ones this app never
launched, and would leave residue on uninstall.

### 2.5 Transport

`type: "http"` hooks POST to the existing loopback MCP server on a new route,
carrying the same per-run bearer token. No process spawn per event, and no new
trust boundary — `mcpauth.ts`'s fail-closed rule applies verbatim, so an
unauthenticated local process cannot forge a session state.

### 2.6 Correlation

Free. `pty.ts` already spawns with `--session-id <uuid>` for a new conversation
and `--resume <uuid>` for an existing one, so the tab already owns the UUID the
hook reports back in `session_id`. `PtyManager` records `sessionId → ptyId` at
spawn; the route resolves it and broadcasts by `ptyId`, matching how `pty:data`
and `pty:exit` already address the renderer.

### 2.7 Degradation

Not every Claude session gets hooks, and the design must not pretend otherwise:

- a session started by hand inside a shell tab (owner decision: out of scope),
- `agentControl: false`, which takes the whole surface away,
- `disableAllHooks` / `--bare` in the user's own configuration.

In every case the tab falls back to today's `PtyStatus` and renders an honest
unknown rather than a stuck state.

### 2.8 The security decision this ticket must make

`pty.ts:278-280` withholds `--mcp-config` from `agentSpawned` workers (KAN-41's
recursion guard). Whether a worker gets the notify hook is a real question — a
worker blocked on permission is exactly what should surface — but the hook URL
carries the token the guard exists to withhold. Decide deliberately and record
the reasoning in the code.

## 3. Consuming the signal

### 3.1 The dot (KAN-74)

Every reachable state gets a defined, distinct appearance, documented beside the
CSS. **No optimistic default**: `?? 'running'` at `TabBar.tsx:425` is deleted, and
a tab with no known state renders as dormant. `closeguard.ts:41-49` already
refuses to reuse that default and explains why; the dot now agrees with it.

The amber flicker must be **reproduced before it is fixed**. The obvious
explanation is wrong — `Terminal` does not unmount on tab or space switch
(`App.tsx:2041-2047` maps the whole `tabs` store and toggles `hidden`) — so the
real trigger has to be identified rather than assumed.

### 3.2 The close guard (KAN-75)

`closeRisk` gains the distinction it never had: mid-turn work is unrecoverable and
still warns; a session idle at the prompt has its transcript on disk and does not.
Fixed in `closeRisk` itself, not at any call site — tab close, group close and
space delete all funnel through it, which is the entire reason the module exists.
`deleteSpaceReason` consumes the same `CloseRisk[]` and stops over-warning for
free.

### 3.3 Markers (KAN-76)

Tab → space dropdown row → space chip. The space-level marker is **derived from
tab state at render, never stored**; a second source of truth for "does this space
need attention" is a second thing to keep in step. `usePtyStatus` is already global
with an empty dep array, so cross-space data is already arriving — no new
subscription plumbing.

Markers clear when the session leaves the blocked state, **not** on tab focus.
Looking at a prompt without answering it has not unblocked anything.

### 3.4 Sound, badge, toast, auto-switch (KAN-77 … KAN-80)

- **Sound**: synthesized with WebAudio, not a bundled asset — zero bytes, no
  dependency, no licence question in a repo about to go public. Muted by default.
- **Badge**: `win.setOverlayIcon()`. `app.setBadgeCount()` is a **no-op on
  Windows** and would have silently shipped nothing. `flashFrame` is reserved for
  `permission_prompt` and must be cleared on focus or it flashes forever.
- **Toast**: requires `app.setAppUserModelId()`, which does not exist anywhere in
  the tree and is mandatory under NSIS (Squirrel provides it automatically; NSIS
  does not). Verify against a packaged build only — dev builds always say
  "Electron".
- **Auto-switch**: opt-in, off by default. Its suppression rules are the whole
  ticket: never while typing, never repeatedly, never away from a session that is
  itself blocked.

### 3.5 First-run setup (KAN-79)

One card that **summarizes the feature** and collects all three switches, rather
than a bare permission prompt. This is the only place a user learns the feature
exists; a naked "Allow desktop notifications?" gets declined out of habit and takes
the feature with it. The card writes the same keys Settings → Notifications edits —
a first-run view of that section, not a second source of truth.

## 4. Spaces (KAN-81 … KAN-85)

### 4.1 Pinned separation

`Space.pinned` is currently a pure delete-guard: nothing sorts or draws it
(`SpaceMenu.tsx:91` filters for uniqueness only, and there is no
`.spacemenu-item.pinned` rule, unlike tab pinning at `TabBar.tsx:420`). Pinned
spaces sort into a leading run with a separator and a marker; order within each run
is preserved.

### 4.2 Keybinds

Both defaults were changed from the literal ask, with reasons recorded in KAN-82:

- **Pinned spaces take Ctrl+Shift+1..9.** `Ctrl+Space` + digit is not a chord a
  browser can express — it is a mode, and it swallows Ctrl+Space.
- **Cycling is Ctrl+Tab / Ctrl+Shift+Tab.** Ctrl+←/→ is word-jump in Claude Code's
  own input; claiming it globally would destroy word navigation in every terminal
  tab. It is also closer to the alt-tab feel that was described.

**Every new binding inherits KAN-59's two-halves rule:** `keys.ts` owns exactly one
predicate, `App.tsx` acts on it, `Terminal.tsx:139` suppresses the same press.
Splitting them produces a silent asymmetric failure.

`spaceIndex` cannot be reused — it reads `Number(e.key)` and rejects Shift, but
`Ctrl+Shift+1` reports `e.key === '!'`. The new predicate reads `e.code`.

`spacemenu.ts`'s `acceleratorLabel` is shared between KAN-81 and KAN-82, so those
two are **stacked branches, never raced**.

### 4.3 Colors

`Space.color?` — absent for uncolored, following the `pinned?` precedent so a
pre-0.10.0 `workspace.json` loads unchanged and writes no new key. Coerced
explicitly in `sanitize()` (the `pinned: s.pinned === true ? true : undefined`
pattern), not left to ride the spread.

Presets reuse `GROUP_COLORS` verbatim — already exactly Clay, Sage and Sand, the
three named in the ask. No second palette.

**One render path for both.** The element emits `--space-color-light` and
`--space-color-dark` as inline custom properties and one CSS rule chooses between
them per theme. A preset sets both to the same `var()` name, which itself repaints.
That is what makes the custom picker a small addition rather than a parallel
implementation.

Custom colors specify **both** themes explicitly (owner decision): a single hex
cannot repaint, and a derived dark variant is a colour the user did not choose.
The picker is a native `<input type="color">` per theme — Windows' own dialog
supplies the hex field and full picker for free — plus an alpha range slider and a
side-by-side preview. No colour library.

The wash covers the **chrome band only** — tab strip, space bar, nav bar — reusing
`.tabgroup`'s `color-mix()` recipe. Not the panes: tinting behind the file list and
xterm is a readability risk and fights the paper background.

## 5. Release readiness (M9)

### 5.1 Sequencing is forced

**CI comes first (KAN-88).** A macOS DMG cannot be produced on Windows —
electron-builder's own documentation states mac signing works only on macOS and
cannot be fixed. CI is therefore a prerequisite for the platform work, not a
finishing touch. It also touches no application code, which makes it the safest
thing to land first.

**Then the path contract (KAN-89).** `pathutil.ts` is built entirely on drive
letters and UNC shares and is imported across both processes and most of the
renderer. Its POSIX volume-identity test must be a real `stat().dev` comparison,
because two shipped behaviours depend on it: same-drive-is-move drag semantics,
and trash staging (get it wrong and undo silently becomes a cross-device copy).
This likely turns a pure string function async, which is exactly why it is
contract-first.

**Then the fan-out (KAN-90):** `policy.ts` system roots, `trash.ts` volumes,
`pty.ts`/`ide.ts` verification of their never-exercised POSIX escape hatches,
`search.ts` per-platform ripgrep, and `external.ts` — which is 100 % Windows with
no fallback at all and needs a genuine rewrite.

**Then Cmd keys (KAN-91)**, so they can be tested against a real mac build. The
renderer is `Ctrl`-only across 16 files and several bindings actively reject
`metaKey`. One primitive, not sixteen conditionals.

### 5.2 Known platform facts

- node-pty ships prebuilt binaries for darwin and win32 but **not Linux**; the
  Linux runner must install `build-essential python3` before `npm ci`.
- `npmRebuild: false` stays everywhere — node-pty is N-API, so its ABI is stable
  across Node and Electron.
- ripgrep's per-platform packages already exist as optional dependencies in the
  lockfile; `extraResources` is set per platform.
- **An unsigned macOS build cannot auto-update at all**, and Gatekeeper forces
  right-click→Open. Signing means Apple Developer Program at $99/year. Recommended:
  ship unsigned and clearly labelled first; the CI matrix does not change when the
  account arrives.

### 5.3 Repo and README

`docs/` **stays** as curated public documentation; the four historical plans and
the `docs/superpowers/` tree go, and `docs/superpowers/` is gitignored so the
planning tooling keeps working without republishing its scratch output. The
`.claude/` tree and the tycho files go entirely.

`release.ps1` is removed **after** CI can produce the draft, so the release path is
never broken in between. The stated worry about it is misplaced — it needs push
rights and a token Dan holds — but it is dead weight once CI exists.

The README documents an app three milestones out of date: no spaces, tab folders,
split view, pinned tabs, search, MCP control, workspace memory or CLI. That is a
content rewrite, not a reorganization.

## 6. Branch plan

Disjoint file ownership, per the project workflow. `shared/types.ts` and
`shared/ipc.ts` are extended in **exactly one** task.

```
KAN-73  contract        ── alone, first. Owns shared/types.ts + shared/ipc.ts.
   ├── KAN-74  dot              ptystatus.ts, TabBar.tsx, index.css
   ├── KAN-75  close guard      closeguard.ts
   └── KAN-76  markers          SpaceMenu.tsx, TabBar.tsx*, index.css*
          ├── KAN-77  sound      SettingsModal.tsx  (owns the section pattern)
          ├── KAN-78  badge      main/index.ts
          ├── KAN-79  setup      new component + SettingsModal.tsx*
          └── KAN-80  auto-switch App.tsx

KAN-81 ──stacked── KAN-82 ──> KAN-83     spacemenu.ts, keys.ts, SpaceMenu.tsx
KAN-84 ──stacked── KAN-85                 spaces model, index.css, picker
```

`*` marks a shared file needing sequencing rather than parallel edits. KAN-74 and
KAN-76 both touch `TabBar.tsx` and `index.css`; KAN-77 and KAN-79 both touch
`SettingsModal.tsx`. Stack, do not race.

M9 is strictly serial where marked: KAN-88 → KAN-89 → KAN-90 → KAN-91 → {KAN-92,
KAN-93}. KAN-86 and KAN-87 are independent of all of it except that the README
needs the platform outcomes before its quickstart is final.

## 7. Testing

The project rule applies without exception: **an assertion earns its place only if
it fails against the unmodified build, and that must be shown every time.** Seven
assertions that passed while the feature was broken have already been caught in
this repo.

Traps specific to this release:

- **A terminal echoes what you type**, so a marker typed into a terminal is on
  screen before anything runs. Have the shell generate it.
- **ConPTY repaints the whole buffer on resize**, so "the marker is still on
  screen" survives every xterm being destroyed. Probe the `.xterm` element.
- **Asserting the implementation, not the defect.** "A `--settings` flag was sent"
  proves nothing about whether a state ever arrived. "`setOverlayIcon` was called"
  passes whether or not the logic deciding *when* is right — test the pure decision
  function instead.
- **Structurally guaranteed assertions.** Comparing a stored colour to itself can
  never fail; assert that two themes resolve to *different* colours.
- **Sync/async parity tests go blind** when both spellings share one helper. For
  `pathutil.ts`, diff the new implementation against the pre-refactor one over real
  inputs.
- Suppression rules — no toast when focused, no auto-switch while typing, sound
  muted — are the parts that break quietly. Assert the negative cases.

Harness counts are the regression signal and are re-measured on `main` at 0.9.0.
A changed count means either a regression or a new assertion; know which.
